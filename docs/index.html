Ranking content for review: a decision-support model for declining search visibility

ABSTRACT Search and content teams routinely face more URLs than they can review, with no reliable way to decide which to prioritize. This project builds a ranking system that scores individual content pages for review priority, using search-performance and engagement signals drawn from a sixteen-month warehouse of Search Console and analytics data. A logistic regression model, validated on a genuinely out-of-time test period, ranks pages by their likelihood of declining search visibility and beats a naive recency baseline on Precision@50 (0.62 versus 0.58). A tree-based alternative achieved higher overall discrimination but performed worse specifically at the top of the ranking — the part of the output that matters for a prioritized action list. The result is not a forecast of any single page’s fate, but a defensible, evidence-backed shortlist for human review.
1

Introduction

Content and search teams accumulate hundreds or thousands of pages over time, and visibility on any given page can fade for reasons that are rarely obvious from a dashboard alone. The practical problem is not detecting decline after the fact — most analytics tools already do that — but deciding which of many declining pages deserves attention first, and why.

This work supports a specific decision: given a large set of live content pages, which should a search or content team review this week? The output is a ranked list with a reason attached to each entry, intended to make a reviewer’s triage faster and better justified, not to replace their judgment.

Two disjoint feature/label window pairs were built from the daily performance table, described in full in Section 3.

Exclusions

  • Content rows flagged is_deleted = true or is_published = false were removed.
  • Pages with fewer than 5 non-zero-impression days within their feature window were excluded as too sparse to establish a reliable baseline.
  • GA4 channel-mix features (session share by channel) were computed but found to be 100% missing across the analysis window and were dropped rather than imputed — see Section 5.

Public-safety handling

No client names, domains, URLs, or raw exports appear anywhere in this paper or its accompanying notebooks. All client, content, keyword, and URL identifiers are anonymized hashes provided directly by the warehouse.

Methodology

Unit of analysis

One row per content page (content_hash_id), each mapping to exactly one client, keyword, and URL.

Label definition

A page is labeled declining if its average daily organic impressions in the label window fall more than 20% below its average in the preceding feature window:

decline_ratio = avg_impressions(label) / avg_impressions(feature)
is_declining = 1 if decline_ratio < 0.80 else 0

Impressions were chosen over clicks as the primary signal because daily clicks are heavily zero-inflated, making them a noisier foundation for a decline label.

Time windows

SplitFeature windowLabel window
TrainJan–Aug 2025Sep–Nov 2025

Observed shift. The base decline rate differs substantially between periods — 55.4% in train versus 27.0% in test — suggesting either seasonality or a genuine change in the underlying content ecosystem over time. This is treated as an open question, not a resolved one, and makes the test period a meaningful generalization check rather than an easy one.

Features

Search performance (impressions, clicks, position, CTR), engagement (sessions, engaged sessions, scroll events), and static content attributes (word count, intent, search volume, competition, CPC, content age, time since last optimization), plus two explicit missingness flags described below.

Missing data

Feature% missingTreatment
GA4 channel-mix shares100%Dropped — not populated in this release
Backlinks96%Dropped — too sparse for reliable signal
Days since last optimized77%Median-imputed + was_never_optimized flag
Word count61%Median-imputed + has_word_count flag
Search volume, competition, CPC, intent5–7%Standard median / mode imputation

Missingness in the two flagged features is treated as informative rather than random — a page with no optimization date likely was never optimized, which is itself a meaningful signal for a refresh-prioritization task.

Baseline

Pages ranked purely by days since last optimized — a rule any content team could apply without any modeling. The model must beat this on Precision@50 to justify its added complexity.

Validation design

A time-aware, out-of-time split was used rather than a random or client-grouped split, since the deliverable is a forward-looking ranking system that must generalize to a period it has not seen.

Leakage audit

  • All features computed only from feature-window dates
  • Content metadata used as-is: static attributes, not measured outcomes
  • Label computed only from label-window dates, strictly after the feature window ends
  • Test label window begins after train label window ends — no temporal overlap
  • No engineered feature's aggregation window extends into the label period

5

Limitations & honest framing

This system identifies statistical associations between observable content signals and subsequent decline. It does not establish causation and should not be read as forecasting any individual page’s future with confidence — it is decision support, not a guarantee.

  • Modest discrimination. ROC AUC of 0.631 indicates real but limited signal. The model's advantage over the baseline on Precision@50 (0.62 vs. 0.58) is incremental, not dramatic.
  • Train/test base-rate shift. Decline rates differ substantially between periods (55% vs. 27%); the cause — seasonality, ecosystem change, or threshold interaction — remains unresolved with the history available.
  • GA4 engagement data is largely unavailable in this release, so the analysis leans almost entirely on organic search signals and says nothing about how AI-referral, social, or other channels relate to decline.
  • Missing-data assumptions. Treating missing optimization dates and word counts as informative (rather than random) is a reasonable but unverified interpretation of the pipeline that produced this warehouse.
  • Schema gap at scoring time. The live snapshot table used for scoring lacks the GA4 engagement columns present in training data; those features are held at zero when scoring live content, a known constraint of applying a richer historical model to a leaner production source.
  • Limited history. Roughly sixteen months of data allowed one clean out-of-time split, but not enough range to test stability across multiple seasonal cycles.

Given these constraints, the ranked output in Section 6 should be read as “these pages show measurable signs worth a human review,” not as a guarantee of decline or a promise that any specific fix will reverse it.
